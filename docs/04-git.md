# 04 — Git & GitHub

## Why it matters

Git records changes; GitHub supports review and automation. Learn Git’s local workflow before CI/CD.

## What to learn

Understand repositories, commits, branches, clone, fetch, pull, push, merge, conflicts, `.gitignore`, and Pull Requests. Use `git status` and `git diff` before committing.

## Practical examples

Never commit `.env`, keys, build output, or database data. A Pull Request is a reviewable unit of change.

## Short lab (20 minutes)

Create a repository with `README.md` and `.gitignore`; commit and push it. Create a branch, edit README, push it, and open a Pull Request.

## Common mistakes

Committing secrets, working only on main, or resolving conflicts by deleting unfamiliar code.

## When to move on

- [ ] I can clone, branch, commit, fetch, pull, push, and open a PR.
- [ ] I can resolve a simple conflict and keep local secrets ignored.
