# Job-Ready Checklist

You do not need to master everything before applying. You should be able to demonstrate most of the following through labs, projects, and troubleshooting.

## 1. Linux & Troubleshooting

- [ ] Navigate the Linux filesystem and manage files, users, groups, and permissions.
- [ ] Inspect processes, CPU, memory, disk, logs, and listening ports.
- [ ] Manage services with `systemctl` and troubleshoot failures with `journalctl`.
- [ ] SSH into a server and diagnose a basic service outage.
- [ ] Intentionally break and recover at least one Linux service.

## 2. Networking

- [ ] Explain IP addresses, subnets, DNS, TCP/UDP, ports, HTTP/HTTPS, and routing basics.
- [ ] Trace a request from client → DNS → load balancer/reverse proxy → application.
- [ ] Use tools such as `curl`, `dig`, `ss`, and `traceroute` to troubleshoot connectivity.
- [ ] Explain the difference between a network failure and an application failure.

## 3. Git & Automation

- [ ] Use Git comfortably: branch, commit, merge, push, pull, and open a pull request.
- [ ] Resolve a simple merge conflict.
- [ ] Write Bash scripts for basic automation.
- [ ] Read and modify simple Python or Go code.
- [ ] Call an API and work with JSON from a script.

## 4. Application Awareness

- [ ] Explain how a basic backend application handles requests.
- [ ] Understand REST APIs, status codes, environment variables, logs, and health checks.
- [ ] Connect a simple application to PostgreSQL.
- [ ] Understand basic database design, CRUD, indexes, and relationships.
- [ ] Diagnose a basic application/database connectivity failure.

## 5. Cloud

- [ ] Work confidently with one cloud provider.
- [ ] Create and secure compute, networking, storage, IAM, load balancing, and managed databases.
- [ ] Explain public vs private networking.
- [ ] Apply least privilege to IAM permissions.
- [ ] Deploy a simple application to the cloud and troubleshoot it.

## 6. Containers

- [ ] Build and run Docker images.
- [ ] Write and understand a Dockerfile.
- [ ] Use volumes, networks, environment variables, and health checks.
- [ ] Run a multi-service application with Docker Compose.
- [ ] Troubleshoot a failed or unhealthy container.

## 7. CI/CD

- [ ] Build a pipeline that runs tests, builds an image, and deploys an application.
- [ ] Store secrets securely in the CI/CD platform.
- [ ] Understand artifacts, environments, and pipeline failures.
- [ ] Diagnose and fix a failed pipeline run.

## 8. Infrastructure as Code

- [ ] Provision infrastructure using Terraform.
- [ ] Understand providers, resources, variables, outputs, and modules.
- [ ] Explain Terraform state and why it matters.
- [ ] Use `init`, `plan`, `apply`, and `destroy` safely.
- [ ] Detect and fix a simple Terraform configuration error.

## 9. Kubernetes

- [ ] Explain Pods, Deployments, Services, Ingress, ConfigMaps, Secrets, and probes.
- [ ] Deploy an application to Kubernetes.
- [ ] Configure requests and limits.
- [ ] Use `kubectl get`, `describe`, and `logs` to troubleshoot failures.
- [ ] Diagnose at least one `CrashLoopBackOff` or connectivity issue.

## 10. Monitoring & Basic Security

- [ ] Read application and infrastructure logs.
- [ ] Use Prometheus/Grafana for basic CPU, memory, request, error, and latency monitoring.
- [ ] Create or understand a basic alert.
- [ ] Explain least privilege, TLS, secret handling, and basic image/dependency scanning.
- [ ] Avoid hardcoded credentials.

## 11. Projects & Professional Readiness

- [ ] Have at least 2–3 projects that combine multiple roadmap skills.
- [ ] Explain each project’s architecture and request flow.
- [ ] Explain one real failure you caused, diagnosed, and fixed.
- [ ] Explain the security decisions you made.
- [ ] Write clear project documentation and README files.
- [ ] Be comfortable explaining your work during an interview.
- [ ] Have made at least one collaborative Git/GitHub contribution or open-source contribution if possible.

## Ready to Apply

Start applying when you can demonstrate most of the checklist above with real hands-on work.

You do not need:

- Kubernetes mastery
- Advanced SRE
- Multi-cloud
- Service mesh
- Platform engineering

Continue learning while applying.
